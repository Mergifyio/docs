Quarantine stops a flaky or broken test from blocking merges without removing
it: the test keeps running and reporting results, so you can fix it while
still seeing how it behaves.

<Image src={QuarantineScreenshot} alt="Quarantine dashboard: quarantine metrics and quarantined-tests list" />

## How quarantine works

A quarantined test still executes in your CI pipeline and its results are
still collected by [Test Engine](/test-engine). The difference is that
failures are ignored for merge decisions and no longer mark the pipeline as
failed.

This means:

- Your CI stays green while you work on a fix

- Historical data is preserved, so you can track whether the test improves
  or worsens over time

- Other team members can see the test is quarantined and why

Quarantine works on any branch, not just the default branch.

:::note
  Quarantined tests must still be uploaded through one of the supported CI
  integrations, and your CI must be configured to check quarantine status.
  See the [documentation for your test
  framework](/test-engine#test-framework-configuration) for setup details.
:::

## Adding and removing tests from quarantine

You can add or remove specific tests from quarantine yourself. This is useful
when you've identified a problematic test through
[Detection](/test-engine/detection) and want to stop it from blocking your
team while you investigate.

### From the Mergify dashboard

The [Quarantine page](https://dashboard.mergify.com/test-insights/mitigation)
on the dashboard contains the list of tests that Test Engine collected from
your CI runs. From there, you can add or remove a test from quarantine.

### From the Mergify CLI

The [Mergify CLI](/cli/tests) can manage quarantines from the terminal,
which is handy for scripting or for letting an AI coding agent quarantine a
flaky test it just hit:

```bash
# Quarantine a test.
mergify tests quarantines add -r owner/repo \
  --reason "flaky under load, fix in progress" \
  "tests/auth/test_login.py::test_login_timeout"

# Remove it from quarantine.
mergify tests quarantines remove -r owner/repo \
  "tests/auth/test_login.py::test_login_timeout"

# List everything currently quarantined.
mergify tests quarantines list -r owner/repo
```

See the [`tests` CLI reference](/cli/tests) for all flags and exit codes.

## Auto-quarantine

Auto-quarantine lets Mergify quarantine tests for you. By default, only flaky
tests are quarantined automatically. You can also enable quarantining of known
broken tests through an additional option.

This is useful for teams that want hands-off management of unreliable tests.
You can enable or disable auto-quarantine per repository from the Quarantine
page in the dashboard.

### When Mergify quarantines a test itself

Mergify quarantines a test on its own from the health status
[Detection](/test-engine/detection) assigns it. It does not act on that status
as soon as a test looks unhealthy: it waits until there is enough evidence
behind the verdict.

Three things have to hold. The test needs a reasonable number of recent
executions to judge, it has to have been running long enough to have a pattern
at all (a test whose whole history fits inside the last few minutes reads as one
bad CI event rather than a flaky test), and a meaningful share of its runs has to
have failed. That last floor is why a single failure among thousands of green runs
never quarantines anything, however reproducible the rest of the pattern looks.

A test that has not run for a while keeps whatever health status it last had,
but Mergify stops spending [reruns](/test-engine/detection#rerunning-unhealthy-tests)
on it, since no recent run backs that verdict any more.

Until a test clears those bars, its status still shows on the dashboard and you
can quarantine it yourself; Mergify will not do it for you.

## Practical workflows

### Quarantining a test from Detection

When you identify a high-impact flaky or broken test in
[Detection](/test-engine/detection), you can quarantine it directly to
stop it from blocking merges while you work on a fix.

### Reviewing quarantined tests

Periodically check the Quarantine page to review quarantined tests. Look
for tests whose health status has improved; these may be ready to be
removed from quarantine.

### Enabling auto-quarantine

For repositories where broken tests frequently block CI, enable
[auto-quarantine](#auto-quarantine) and its option for known broken tests:
by default it only quarantines flaky ones.

## Staying notified

Quarantine and dequarantine actions, whether you make them yourself or Mergify
applies them automatically, are recorded as events you can review on the
dashboard and act on. You can also have Mergify post them to a Slack channel as
they happen: see [Test Engine notifications](/integrations/slack#test-engine-notifications)
to set one up.
